Observer는 로컬 SQLite 데이터베이스에 기록을 저장합니다. 분석 데이터를 보내거나 이벤트를 자동으로 업로드하지 않습니다. 실제 추론에서는 설정한 업스트림 제공업체에 애플리케이션 요청을 보냅니다.

아래 명령은 설치된 `jev-observer` 실행 파일을 사용합니다. 소스 빌드는 `./target/release/jev-observer`를 사용하고, Windows에서는 [설치 안내](/ko/docs/installation)에 있는 실행 파일 경로를 사용하세요.

## 저장되는 데이터 이해하기 {#know-what-is-retained}

입력 상태와 assets를 비롯해 인식된 요청·응답 구조의 미디어 필드는 기본적으로 저장 기록에서 제외합니다. 가져온 기록에도 같은 규칙이 적용됩니다. 요청 전달에는 영향을 주지 않습니다. 정의, 답변, 확장 필드는 저장되며 민감한 내용이 포함될 수 있습니다.

입력 상태를 명시적으로 저장하려면 다음과 같이 Observer를 시작하세요.

```bash
jev-observer --capture-state
```

알려진 인증 정보 필드와 전달에 사용한 비밀 값은 저장 데이터에서 가립니다. `--redact-key` 옵션을 반복해 필드 이름을 추가할 수 있습니다.

```bash
jev-observer \
  --redact-key email \
  --redact-key customer_secret
```

Observer는 알려진 입력 경로를 제거하기 전에 원본 입력에서 비밀 값을 찾습니다. 따라서 저장되는 다른 필드에 같은 값이 있어도 가릴 수 있습니다. 모든 민감한 값을 인식한다고 보장하지는 않습니다. 민감 정보 가리기로 변경된 정의는 원래 정의와 동일한지 더 이상 확인할 수 없으므로 별도로 유지합니다.

개인정보 필터링으로 서로 다른 객체 키나 답변 식별자가 합쳐지거나, 유효하지 않은 검증 메타데이터가 유효한 답변으로 바뀌게 되면 가져오기 전체가 실패합니다. 실제 요청 전달은 계속되지만, Observer는 원본 내용과 답변이 없는 최소한의 불완전한 기록을 저장하고 수집 누락을 표시합니다. 이러한 검사는 새 캡처와 가져오기에 적용되며, 이미 저장된 기록을 다시 작성하지는 않습니다.

## 압축 및 이미지 요청 살펴보기 {#inspect-compressed-and-image-requests}

Observer는 요청을 전달한 뒤 하나의 완전한 gzip 멤버나 zstd 프레임, 그리고 지원되는 이미지 multipart 요청을 검사할 수 있습니다. 원본 본문과 디코딩된 본문은 각각 `--capture-limit`(기본 256 KiB) 안에 들어야 합니다. 이 한도는 전체 메모리 상한이 아닙니다. Multipart는 JSON `request` 파트 뒤에 이 JSON에서 참조하는 PNG/JPEG 파트가 오는 형식을 지원합니다. 지원하지 않거나 형식이 잘못되었거나 한도를 넘는 검사 데이터는 고정된 사유가 담긴 최소한의 불완전한 기록으로 남깁니다. 전달되는 바이트는 바꾸지 않습니다.

이미지 바이트는 `--capture-state`를 사용할 때만 크기를 제한한 base64로 저장합니다. Observer는 이미지 경로나 URL을 열거나 픽셀을 디코딩하지 않으며, 저장된 데이터로 SDK 요청을 그대로 재실행할 수 있다고 보장하지 않습니다. [캡처한 전송 데이터의 한도](https://github.com/LimePencil/jev-observer/blob/v0.4.0/docs/capture-decoding.md)를 참고하세요.

## 암호화와 로컬 접근 {#encryption-and-local-access}

실제 사용 기록을 저장하는 SQLite 데이터베이스는 외부에서 전달한 `JEV_OBSERVER_DB_KEY`를 사용해 SQLCipher로 암호화합니다. 일반 수집을 시작하기 전에 [32바이트 데이터베이스 키를 생성하고 보관](/ko/docs/connecting#save-a-database-key)한 뒤, 실제 수집 모드를 시작할 때마다 같은 64자리 16진수 값을 제공하세요. 키를 잃으면 암호화된 기록을 읽을 수 없습니다.

기존 평문 데이터베이스로 처음 시작하면 요청을 받기 전에 마이그레이션합니다. 먼저 이전 버전의 Observer 프로세스를 중지하세요. 이전 백업과 삭제된 디스크 블록에는 평문이 남아 있을 수 있습니다. 데모 데이터베이스는 가져온 기록까지 포함해 평문으로 유지됩니다. JSONL과 CSV 내보내기는 의도적으로 평문 파일을 다운로드하므로 보관하거나 공유할 때 보호해야 합니다.

대시보드와 로컬 API에는 HTTP Basic 인증이 필요합니다. 사용자 이름은 `observer`이며, 비밀번호는 전체 데이터베이스 파일 이름 뒤에 `.token`을 붙인 파일의 임의 작업 공간 토큰입니다. 시작 출력에 정확한 경로가 표시됩니다. 실제 수집용 기본 토큰은 `.jev-observer/observer.sqlite.token`, 데모 토큰은 `.jev-observer/observer.demo.sqlite.token`입니다. 토큰을 비공개로 보관하세요.

기존 `*.access-token` 작업 공간에서 처음 업그레이드하면 새 토큰을 만들고 기존 파일은 그대로 둡니다. 다시 로그인하고 작업 공간 인증을 사용하는 클라이언트도 갱신하세요. [업그레이드 안내](/ko/docs/installation#update-an-existing-build)를 참고하세요.

Windows의 기본 `.jev-observer` 디렉터리에는 현재 사용자 전용 ACL을 적용합니다. 사용자 지정 데이터베이스 디렉터리는 현재 사용자, SYSTEM, 관리자만 접근하도록 미리 제한해야 합니다. 토큰 파일에는 보호된 현재 사용자 ACL을 적용하며, 권한이 과도하게 열려 있는 파일과 재분석 지점은 거부합니다.

## 기록 가져오기 {#import-records}

대시보드 사이드바에서 **Import records(기록 가져오기)**를 선택하거나, **Export(내보내기)**에서 **Import local records(로컬 기록 가져오기)**를 여세요. 원본과 맞는 형식을 선택한 뒤 로컬 파일을 고르거나 내용을 붙여 넣습니다. 빈 작업 공간에도 **Import records** 버튼이 표시됩니다. 지원 형식은 다음과 같습니다.

| 형식                              | 내용                                                      |
| --------------------------------- | --------------------------------------------------------- |
| Observer JSONL export             | Observer에서 이전에 내보낸 정규화된 기록                  |
| JevRouter decision receipt        | 검토된 JevRouter receipt 형식. 애플리케이션 작업으로 저장 |
| Decision request/response capture | 지원되는 프로토콜의 원래 질문과 보고된 결과               |

가져온 기록은 현재 열려 있는 작업 공간에 저장됩니다. 가져온 기록을 암호화하려면 [보관한 데이터베이스 키를 설정하고 Observer를 실제 수집 모드로 시작](/ko/docs/connecting#save-a-database-key)한 뒤 그 작업 공간으로 가져오세요. 데모로 가져오면 샘플과 함께 평문 데이터베이스에 저장됩니다. 데모 모드라고 해서 가져온 기록이 합성 데이터로 바뀌지는 않습니다.

가져오기 한 번에 기록 10,000개와 UTF-8 텍스트 8 MiB까지 허용하며, 정규화에는 별도 한도가 있습니다. 거부된 배치는 일부 기록도 저장하지 않습니다. 큰 JSONL 파일은 완전한 줄 사이에서 나누고, 개별 기록이 너무 크면 원본에서 줄이세요. [형식과 크기 한도](https://github.com/LimePencil/jev-observer/blob/v0.4.0/docs/models.md#library-results-and-custom-apis)를 참고하세요.

변하지 않는 원본 이벤트 ID로 중복 가져오기를 방지합니다. 서로 독립적인 호출은 페이로드가 같아도 별도의 관측 기록으로 유지합니다. 식별자에는 민감하지 않은 값을 사용하세요. 개인정보 필터링이 Observer 기록의 ID, 출처, 유효 이벤트 ID 또는 receipt의 결정 ID를 바꾸면 가져오기 전체를 거부합니다. Observer는 유효성 검증과 그룹화를 다시 수행합니다. 알 수 없는 이벤트 시각은 계속 알 수 없음으로 두고 타임라인에서 제외하며, 기록 배치를 위해 별도의 가져온 시각을 사용합니다.

가져오기에는 현재 캡처 및 민감 정보 가리기 설정을 적용합니다. 입력 상태를 저장하려면 가져오기 전에 `--capture-state`로 시작하세요. 설정한 민감 정보 가리기는 그대로 적용됩니다.

JevRouter receipt는 애플리케이션 작업으로 유지하며, 실제로 없던 추론 요청, 토큰 비용, 전송 정보를 만들어 내지 않습니다.

## 변환한 모델 결과 가져오기 {#import-mapped-model-results}

Observer 외부에서 수행한 호출에는 **Decision request/response capture**를 선택하세요. 형식 ID는 계속 `systemone-capture`입니다. 각 JSONL 줄에는 하나의 원래 호출에 대한 안정적인 이벤트 ID, 출처, 제공업체, 원래 질문 정의, 보고된 답변이 필요합니다. 기본 프로토콜은 System One입니다. 네이티브 Decisions와 Cloudflare 캡처는 원래 구조를 유지한 채 `protocol`과 `model_profile`을 지정할 수 있습니다. Choice와 Score에는 전체 확률 분포가 필요합니다. 선택된 레이블이나 일부 top-k 결과만으로는 충분하지 않습니다. 없는 정보는 알 수 없음으로 유지합니다.

오프라인 변환기는 모델을 호출하지 않고 검토된 System One, NanoJev, AgentJev, AnyJev, SemIf, AutoTrust, OmniJev, Jev-Omni 결과를 처리합니다. 두 Omni 형식은 서로 다른 어댑터를 사용하며, 지원하지 않거나 모호한 매핑은 거부합니다. 판단 보류에 할당된 확률은 그대로 표시하며, 완전한 분포를 전제로 하는 통계에는 유효하지 않은 것으로 처리합니다. 가져오기 개인정보 설정을 적용하기 전의 변환기 원본 파일에는 민감한 내용이 포함될 수 있습니다. [캡처 형식과 변환 예제](https://github.com/LimePencil/jev-observer/blob/v0.4.0/docs/models.md#library-results-and-custom-apis)를 참고하세요.

## 선택한 기록 내보내기 {#export-a-selected-history}

필요한 출처, 모델, 기간 또는 사용자 지정 날짜 범위와 검색 필터를 설정한 뒤 **Export(내보내기)**를 선택하세요.

| 형식  | 용도                                                                |
| ----- | ------------------------------------------------------------------- |
| JSONL | 상세 내용을 포함해 옮길 수 있는 기록. Observer로 다시 가져오기 가능 |
| CSV   | 스프레드시트에서 살펴볼 요청 단위 요약                              |

내보내기는 요청 목록에 보이는 최근 행뿐 아니라 필터와 일치하는 모든 보관 기록을 대상으로 합니다. 일치하는 기록의 식별자를 한 번 선택한 뒤, 매번 새로운 읽기 트랜잭션에서 크기가 제한된 페이지를 가져옵니다. 이후 도착한 기록은 제외합니다. 동시에 진행되는 보관 기간 정리, 삭제, 검토 레이블 수정은 뒤쪽 페이지에 영향을 줄 수 있습니다. 내보내기는 한 번에 하나씩 실행됩니다.

JSONL은 현재 상세 페이지에 보이지 않는 답변까지 포함해 저장된 모든 답변을 유지합니다. 너무 큰 기록은 내보내기를 중단시킬 수 있습니다. [내보내기 한도](https://github.com/LimePencil/jev-observer/blob/v0.4.0/docs/storage.md)를 참고하세요.

내보낸 기록에는 민감한 정의, 답변 또는 명시적으로 저장한 입력 상태가 포함될 수 있습니다. 공유하기 전에 파일을 검토하세요.

## 보관 기간과 디스크 사용량 {#retention-and-disk-use}

기본값은 최대 7일의 기록을 보관하며, 기록 수의 소프트 상한은 100만 개입니다. 정리는 30초마다 실행됩니다. 트래픽이 많으면 7일 전에 기록 수 상한에 도달할 수 있습니다.

```bash
jev-observer \
  --retention-days 3 \
  --max-records 250000
```

이는 보관 기간과 기록 수의 제한이며, 디스크 바이트 수 제한은 아닙니다. 행을 삭제해도 SQLite가 할당한 파일 크기가 줄어들지는 않을 수 있습니다. 실제 저장 공간 사용량은 정의, 답변, 확장 필드, 입력 상태 캡처에 따라 달라집니다. 보관 기간 정리와 전체 기록 삭제는 하나의 트랜잭션 안에서 처리 행 수가 제한된 삭제문을 사용하므로, 다른 작업에는 변경 결과가 원자적으로 보이고 실패 시 롤백할 수 있습니다. 행 수 제한은 전체 메모리 상한이 아닙니다.

## 데이터베이스 백업하기 {#back-up-the-database}

전체 파일시스템 백업을 만들려면 Observer를 정상 종료한 뒤 설정된 데이터베이스와 남아 있는 SQLite 보조 파일을 복사하세요. 기본 위치는 작업 디렉터리의 `.jev-observer` 아래입니다. 프로세스가 종료된 뒤 평소 사용하는 파일시스템 백업 도구를 이용하세요. 실제 수집용 데이터베이스 키와 현재 및 이전 대시보드 토큰 파일도 따로 보관하세요. 데이터베이스 키 없이는 암호화된 백업을 읽을 수 없습니다. 현재 데이터베이스를 마이그레이션해도 이전 평문 백업은 평문으로 남습니다.

JSONL은 데이터베이스나 인증 정보 저장소의 전체 백업이 아닙니다. 데이터베이스 스키마가 같아도 새 Box 기록 때문에 이전 버전의 대시보드나 그룹 조회가 실패할 수 있으며, JSONL로 내보낸다고 하위 호환성이 생기지는 않습니다. 롤백하려면 업그레이드한 작업 공간을 별도로 보관하고, 업그레이드 전에 프로세스를 중지한 상태에서 만든 스냅샷을 이전 실행 파일 및 설정과 함께 복원하세요. 필요한 제공업체 인증 정보도 보관하고, 토큰과 인증 정보 저장소 변경 사항은 [업그레이드 안내](/ko/docs/installation#update-an-existing-build)를 확인하세요.

## 기록 삭제하기 {#delete-history}

**Settings(설정)**에서 **Delete history(기록 삭제)**를 선택한 뒤 `DELETE`를 입력해 확인합니다. 해당 작업 공간에 저장된 요청, 답변, 검토 레이블이 삭제됩니다. 이후 요청 전달과 수집은 계속되므로 삭제 뒤 새 기록이 나타날 수 있습니다.

가져오기나 삭제 패널을 닫아도 진행 중인 작업은 취소되지 않으며, 다시 열면 상태를 확인할 수 있습니다. 일시 중지한 대시보드에서 기록을 가져오거나 삭제하면 한 번 새로고침한 뒤 일시 중지 상태를 유지합니다. 데모에서 모든 기록을 삭제하면 다음 데모 시작까지 샘플이 사라집니다. 비어 있는 작업 공간으로 데모를 다시 시작하면 합성 기록을 다시 만듭니다.

데모 모드는 별도의 데이터베이스를 사용합니다. 기록을 삭제하거나 백업하기 전에 작업 공간 모드와 데이터베이스 설정을 확인하세요.

## Observer 정상 종료하기 {#stop-observer-cleanly}

`Ctrl-C` 또는 `SIGTERM`을 사용하세요. Windows에서는 `Ctrl-Break`도 지원합니다. Observer는 업스트림 작업을 취소하고 총 15초의 종료 제한 시간 안에 대기 중인 캡처를 처리합니다. 강제 종료나 갑작스러운 종료로는 저장 대기 중인 관측 기록을 잃을 수 있습니다.

수집기는 영속성을 보장하는 감사 로그가 아닙니다. 중지된 Observer 프로세스를 통해서는 요청을 전달할 수도 없습니다. 운영 한도와 용량 설정은 [설정 안내](/ko/docs/configuration)를 참고하세요.
