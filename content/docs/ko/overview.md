Jev Observer는 Jev와 호환 의사결정 모델을 위한 로컬 프록시이자 대시보드입니다. 로컬 Laya 서버도 연결할 수 있습니다. 답변을 살펴보고, 질문 정의를 비교하고, 실패·지연 시간·토큰 사용량·비용을 한곳에서 확인할 수 있습니다.

SQLite 데이터베이스와 대시보드가 포함된 단일 실행 파일로 동작합니다. **0.4.0** 버전은 MIT 라이선스로 제공되는 작동 가능한 프로토타입이며, Linux·macOS·Windows용 네이티브 패키지를 제공합니다.

## 실제 작업 흐름으로 시작하기 {#start-with-a-real-workflow}

1. [설치하고 샘플을 열어 보세요](/ko/docs/installation). 제공업체 인증 정보 없이 합성 요청 720개를 살펴볼 수 있습니다.
2. [애플리케이션을 연결하세요](/ko/docs/connecting). 데이터베이스 키를 저장하고 업스트림을 선택한 뒤 SDK가 Observer를 향하도록 설정합니다.
3. [기록을 살펴보세요](/ko/docs/dashboard). 요청을 필터링하고, 질문을 비교하고, 검토 레이블을 추가합니다.
4. [기록을 가져오거나 내보내세요](/ko/docs/data-and-privacy). 지원되는 캡처와 필터링한 기록을 작업 공간 간에 옮깁니다.

## 요청이 처리되는 과정 {#what-happens-to-a-request}

애플리케이션은 `127.0.0.1:8765`의 Observer를 통해 설정된 업스트림 하나로 요청을 보냅니다. 기본 System One 경로는 `POST /v1/systemone`이며, 네이티브 Decisions를 선택하면 `POST /v1/decisions`를 사용합니다. Observer는 크기가 제한된 요청·응답 캡처를 저장해 로컬에서 살펴볼 수 있게 합니다. 질문 정의가 바뀌면 통계도 별도로 유지합니다. 답변이 여러 개인 요청도 사용량과 비용은 한 번만 집계합니다.

Choice, Score, Noul과 지원되는 Box 답변은 모델이 보고한 값을 유지합니다. 프로토콜, 모델 검증, 인증 정보 제공업체는 각각 별도로 설정합니다. 대시보드의 모델 카탈로그에는 검토된 항목 54개가 있습니다. 카탈로그에 등재되었다고 해서 실제 서비스와의 호환성이 검증된 것은 아닙니다. [연결 설정](/ko/docs/connecting)을 참고하세요.

## 데이터는 로컬에 보관됩니다 {#your-data-stays-local}

Observer 계정이나 구독은 필요하지 않으며, 분석 데이터 수집이나 자동 이벤트 업로드도 없습니다. 실제 요청은 설정한 제공업체로 전송되므로 요금이 발생할 수 있습니다. 샘플과 저장된 기록은 오프라인에서도 사용할 수 있습니다.

입력 상태는 기본적으로 저장하지 않습니다. 다만 정의와 답변에는 민감한 내용이 포함될 수 있습니다. 실제 사용 기록은 저장해 둔 데이터베이스 키로 암호화하며, 데모 데이터베이스와 내보낸 파일은 평문입니다. [데이터와 개인정보](/ko/docs/data-and-privacy)를 확인하세요.

## 현재 지원 범위 {#current-scope}

Observer는 모델을 호스팅하거나 모든 제공업체를 대상으로 라우팅하지 않으며, 같은 입력을 여러 질문 버전에 재실행하지도 않습니다. 캡처 한도나 중단으로 기록이 누락될 수 있으므로 수집 상태를 확인하세요.
