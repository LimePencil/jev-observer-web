공통 필터를 사용하면 같은 기간과 범위의 요청, 반복 질문, 사용량을 함께 살펴볼 수 있습니다.

## 필요한 기록 선택하기 {#select-the-history-you-need}

출처, 모델, 기간으로 기록을 필터링할 수 있습니다. 기간은 최근 1시간, 24시간, 7일 또는 전체 기록 중에서 선택하며, 기본값은 24시간입니다. **Custom date range(사용자 지정 기간)**에는 현지 시각 기준의 시작과 종료 시간을 입력합니다. 필터는 페이지 URL에 저장됩니다.

출처, 요청 ID 또는 질문 키로 요청을 검색합니다. 상세 패널이 닫혀 있을 때 `Ctrl-K`(macOS에서는 `⌘K`)를 누르면 검색창으로 이동합니다. 별도의 **Find a question group(질문 그룹 찾기)** 검색창은 요청 합계를 바꾸지 않고 선택한 범위의 모든 그룹을 검색합니다. 실패한 요청을 살펴보려면 **Failures(실패)**를 선택하세요.

요청 목록은 처음에 12개 기록을 표시합니다. 기록이 충분하면 **Show 100 records(100개 기록 표시)**로 현재 페이지의 표시 수를 늘릴 수 있습니다. **Older requests / Newer requests(이전 요청 / 최신 요청)**와 **Older groups / Newer groups(이전 그룹 / 최신 그룹)**로 나머지 기록을 탐색합니다. 질문 그룹을 검색하는 동안에도 요청 페이지를 이동할 수 있습니다. 요약은 현재 페이지뿐 아니라 선택한 전체 기록을 집계합니다. 페이지를 불러오지 못하면 마지막으로 불러온 페이지를 유지하고 재시도할 수 있습니다.

## 요약 읽기 {#read-the-summary}

| 지표                           | 의미                                              |
| ------------------------------ | ------------------------------------------------- |
| Requests                       | 선택한 기간에 기록된 추론 요청                    |
| Failures                       | HTTP 오류 또는 중단된 전송                        |
| Request latency                | 관측한 왕복 지연 시간의 p50과 p95                 |
| Reported tokens / Known tokens | 확인 가능한 입력·출력 사용량과 집계 범위          |
| Request cost 또는 known cost   | 보고된 USD 비용 또는 설정한 추정 비용과 집계 범위 |

하나의 요청에 답변이 여러 개 있어도 사용량과 비용은 한 번만 집계합니다. 가져온 애플리케이션 작업으로 추론 비용을 만들어 내지 않습니다. 값이 없으면 알 수 없음으로 유지하며, 샘플 비용은 가상 값입니다. 요청을 열어 비용의 산출 근거를 확인하세요.

## 반복 질문 살펴보기 {#inspect-recurring-questions}

그룹을 선택하면 분포와 유효한 답변 수를 볼 수 있습니다. **Inspect group(그룹 살펴보기)**을 열면 활동, 관측 기록, 정의 버전이 표시됩니다. **Compare with(비교 대상)**에서 관측 결과를 비교할 수 있습니다. 입력 이력이 서로 다르므로 통제된 조건의 정확도 비교는 아닙니다. 상세 패널에 표시되는 관측 기록 수에는 제한이 있습니다. 더 살펴보려면 요청 목록을 이용하세요.

Choice는 선택한 항목, Score는 평가 기준에 따른 값, Noul은 확률을 표시합니다. 네이티브 Decisions는 Choice 값의 자료형을 보존하므로 불리언 `true`와 문자열 `"true"`를 답변과 분포에서 구분합니다. Score 평가 기준은 원래 순서와 레이블을 유지합니다. 유효하지 않거나 누락되거나 거부된 답변은 유효한 분포에서 제외합니다. 실패한 요청은 부정적인 Noul 답변이 아닙니다.

검토된 TypeSafe 및 H2O 프로필의 Box 답변에는 좌표, 신뢰도, 지원되는 존재 여부 필드가 표시됩니다. 각 관측 기록을 개별적으로 살펴보고 검토하세요. Box에는 단일 수치의 평균이나 히스토그램이 없습니다. H2O에서 위치를 찾지 못했다는 결과만으로 대상이 없다고 판단할 수는 없습니다. [모델별 해석](https://github.com/LimePencil/jev-observer/blob/v0.4.0/docs/models.md#compatible-http-servers)을 참고하세요.

그룹은 출처, 질문 키, 전체 정의, 표시 순서, 작업 버전을 기준으로 나눕니다. 변경되거나 민감 정보가 가려진 정의는 통계를 별도로 유지합니다. [그룹화 메타데이터](/ko/docs/connecting#name-sources-and-task-versions)를 참고하세요.

## 요청 살펴보기 {#inspect-a-request}

요청을 열면 답변, 확률, 정의, 캡처한 확장 필드, 애플리케이션 작업을 볼 수 있습니다. 네이티브 Decisions는 질문 순서, 선택적 이름, 거부 응답을 보존합니다. 누락된 데이터를 해석하기 전에 캡처가 완전한지 확인하세요. 결정 항목이 많은 요청에는 **Previous decisions / Next decisions(이전 결정 / 다음 결정)** 버튼이 있습니다. 상세 화면의 시각에는 전체 날짜와 UTC 오프셋이 포함되며, 큰 JSON 영역은 펼칠 때 불러옵니다.

답변에 `correct`, `incorrect`, `unknown` 레이블을 붙이고 **Saved(저장됨)** 표시를 확인하세요. 피드백은 현재 저장된 레이블을 기준으로 표시합니다. 저장 중인 검토는 상세 패널을 닫았다가 다시 열어도 유지되며, 실패 상태도 계속 표시됩니다. 진행 중인 가져오기와 삭제도 패널을 닫은 뒤 상태가 유지됩니다. 모델 신뢰도는 측정된 정확도가 아닙니다.

## 살펴보는 동안 화면 업데이트 일시 중지하기 {#pause-while-investigating}

**Live updates(실시간 업데이트)**를 누르면 화면 업데이트가 일시 중지되며, 상세 패널을 열어도 화면이 고정됩니다. 수집은 계속됩니다. 상세 패널을 닫고 **Resume live(실시간 업데이트 재개)** 또는 **Show latest(최신 기록 표시)**를 선택하면 최신 기록으로 돌아갑니다.

일시 중지 상태에서도 필터를 바꾸면 선택한 기록을 불러옵니다. 기록을 가져오거나 삭제하면 한 번 새로고침한 뒤 일시 중지 상태를 유지합니다. 수집 상태는 별도로 갱신되며, 숨겨진 브라우저 탭에서는 주기적 조회를 멈춥니다.

## 수집 상태 확인하기 {#follow-collection-health}

누락된 캡처, 불완전한 캡처, 대기열 상태, 쓰기 실패를 확인하세요. 이 카운터는 재시작 시 초기화되므로 이전 기록이 완전하다는 근거가 되지는 않습니다. 제공업체 호출이 성공해도 저장된 관측 기록은 불완전하거나 누락될 수 있습니다.

기록 조회가 느리면 5초 뒤 안내가 표시되며, 최대 45초 동안 실행될 수 있습니다. 기록이 많은 작업 공간에서는 필터 범위를 줄이세요. 이 제한 시간은 처리 속도를 보장하지 않습니다. [문제 해결](/ko/docs/troubleshooting#dashboard-refresh-feels-slow)을 참고하세요.
